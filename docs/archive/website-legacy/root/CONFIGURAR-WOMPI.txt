MOTORBALDI — CONFIGURACIÓN DE PAGOS Y RENOVACIÓN AUTOMÁTICA

Qué está listo
El botón «Elegir plan» abre un modal de suscripción. El cliente acepta la renovación, Wompi tokeniza su tarjeta o Nequi y el servidor crea la fuente de pago y el primer cobro. El endpoint de renovación usa esa fuente para hacer los cobros futuros. El servidor fija el precio y no acepta montos del navegador.

1. Crea y habilita tu comercio
Regístrate en https://comercios.wompi.co/ y completa los requisitos que Wompi solicite para recibir dinero. Solicita a Wompi la activación de fuentes de pago y, si corresponde, 3DS/3RI para cobros automáticos. La disponibilidad depende del medio y del modelo de comercio.

2. Obtén las credenciales del MISMO ambiente
En el panel, sección de desarrolladores/integración técnica, busca:
- Llave pública: pub_test_... para pruebas o pub_prod_... para dinero real.
- Llave privada: prv_test_... o prv_prod_...; la usa solo el servidor.
- Secreto de integridad: test_integrity_... o prod_integrity_...; firma las transacciones.
- Secreto de eventos: test_events_... o prod_events_...; verifica los webhooks.
- WOMPI_CRON_SECRET: genera tú un secreto largo y aleatorio para proteger el endpoint cron.
La llave pública puede aparecer en el navegador. La llave privada y los tres secretos nunca deben estar en pricing.html, JavaScript, GitHub o mensajes públicos.
MotorBaldi usa el Widget oficial en modo tokenización. En este modo el usuario elige Tarjeta o Nequi; el servidor crea una Payment Source y la cobra ahora y en las renovaciones. PSE sí está activo para pagos individuales del comercio, pero no crea una Payment Source y no se ofrece en esta suscripción.
La documentación actual también contempla fuentes DaviPlata y Botón Bancolombia mediante flujos API propios. No se habilitan automáticamente por aparecer en un Link de Pago: DaviPlata exige activación comercial y OTP; Bancolombia exige crear/consultar un token y redirigir al usuario para autorizar la cuenta. No deben anunciarse aquí hasta que Wompi confirme su activación recurrente para este comercio y se implemente y pruebe ese flujo completo.

3. Configura el hosting PHP
Publica el CONTENIDO de dist/ en public_html. Necesitas PHP 7.4 o superior, cURL, PDO SQLite y HTTPS. El servidor npm de desarrollo solo sirve archivos: no ejecuta PHP. El build incluye pricing.html y los endpoints api/wompi-*.php.

FUERA de public_html crea motorbaldi-wompi.php con este contenido, sustituyendo los valores por tus credenciales completas:

    <?php
    return [
        'public_key' => 'COPIA_AQUI_TU_LLAVE_PUBLICA',
        'private_key' => 'COPIA_AQUI_TU_LLAVE_PRIVADA',
        'integrity_secret' => 'COPIA_AQUI_TU_SECRETO_DE_INTEGRIDAD',
        'events_secret' => 'COPIA_AQUI_TU_SECRETO_DE_EVENTOS',
        'cron_secret' => 'GENERA_UN_SECRETO_LARGO_Y_ALEATORIO',
    ];

Ejemplo de ubicación:
/home/tuusuario/motorbaldi-wompi.php
/home/tuusuario/public_html/pricing.html
/home/tuusuario/public_html/api/wompi-subscribe.php

    Restringe la lectura del archivo al usuario que ejecuta PHP. Si usas otra estructura, configura WOMPI_CONFIG_PATH con la ruta absoluta del archivo privado. Alternativamente configura WOMPI_PUBLIC_KEY, WOMPI_PRIVATE_KEY, WOMPI_INTEGRITY_SECRET, WOMPI_EVENTS_SECRET y WOMPI_CRON_SECRET como variables de entorno de PHP. No basta crear un archivo .env: este endpoint no lo carga. No necesitas editar pricing.html para poner las llaves.

La base SQLite se crea por defecto FUERA de public_html en /home/tuusuario/motorbaldi-wompi.sqlite. Si usas otra ruta, configura WOMPI_DB_PATH. Haz copias de seguridad de esta base y protege sus permisos.

4. Configura el webhook y el cron
En el Dashboard de Wompi configura una URL de eventos distinta por ambiente:
https://tudominio.com/api/wompi-webhook.php
El webhook valida la firma y activa la suscripción cuando el primer cobro o una renovación queda APPROVED. Wompi debe poder acceder a esta URL por HTTPS.

Configura una tarea cron en tu hosting para llamar el endpoint de renovación cada hora. Ejemplo, cambiando dominio y secreto:

curl -fsS -X POST -H 'X-Cron-Secret: TU_WOMPI_CRON_SECRET' https://tudominio.com/api/wompi-renew.php

El proceso toma hasta 25 renovaciones vencidas por ejecución y registra cada intento. Si una renovación falla, la suscripción pasa a past_due para que contactes al cliente. El cron es necesario: Wompi no agenda por sí solo la fecha de cada plan.

5. Prueba antes de cobrar
Empieza con TODAS las credenciales de pruebas. Abre /precios por HTTPS, elige carro/moto y un plan, escribe nombre y correo y marca la autorización consolidada. Continúa al panel de tokenización de Wompi. Comprueba el primer cobro, aprobado/rechazado/pendiente, el webhook y una ejecución manual del cron. Verifica cada transacción y fuente de pago en tu panel.
Después cambia TODAS las credenciales por las de producción. Este proyecto no ha realizado un pago real con tu cuenta.

6. Activación y cancelación
La página no activa el servicio solo porque el navegador cierre el widget: usa el webhook y el estado APPROVED de Wompi. El cliente puede solicitar la cancelación antes del siguiente cobro; debes atenderla por soporte y ejecutar PUT /v1/payment_sources/{id}/void con la llave privada. El proyecto no permite que un visitante cancele una fuente sin autenticación.
HubSpot (api/hubspot.php) gestiona solicitudes y no procesa estos pagos.

7. Mantenimiento y errores
Si staging está en /home/tuusuario/public_html/staging, el archivo privado se busca también en /home/tuusuario/motorbaldi-wompi.php, fuera de public_html. La base SQLite usa esa misma carpeta privada. WOMPI_CONFIG_PATH y WOMPI_DB_PATH siguen teniendo prioridad.
Si ya existen suscripciones en una base ubicada en otra carpeta, configura WOMPI_DB_PATH con la ruta de esa base antes de actualizar; no empieces con una base vacía.
Para diagnosticar el HTTP 503, ejecuta en la Terminal de cPanel/SSH, desde una copia privada del proyecto: php scripts/wompi-check.php. Verifica configuración, SQLite y conexión a Wompi sin cobrar. No publiques scripts/ ni las credenciales.
El error_log de PHP identifica la etapa fallida: configuration, database, provider_acceptance o checkout_storage. No incluye llaves ni datos de clientes.
La navegación pública usa /precios, /terminos y /politica-de-privacidad. Publica también .htaccess para activar las rutas y las redirecciones de las URLs antiguas.

Si cambias precios, actualiza vehiclePlans en pricing.html Y la tabla prices en api/wompi-common.php. El endpoint rechaza cualquier discrepancia y el servidor siempre decide el monto. Recuerda que COP 99.900 son 9990000 centavos.
«Pagos aún no habilitados»: revisa el archivo privado y que las llaves sean del mismo ambiente.
«Servicio no disponible»: confirma que el hosting ejecuta PHP, cURL y PDO SQLite.
Si no carga el modal, revisa conexión/bloqueadores y recarga la página.
Los medios de pago y la renovación automática dependen de la disponibilidad y activación de tu comercio en Wompi.
